# Included Codex image preparation

This controlled workflow extends the existing SCC Page-content queue, AgentRunner, image uploads and draft service. Recurring image preparation requires the separately recorded, bounded standing trial below. It never grants publishing authority. API keys, paid API fallbacks, credits, quota resets and automatic security handling are prohibited.

Prepare/validate an original `page-content.v1` image concept, retaining its sources, caption and history. A concept may include ordered `imageBrief.frames` with description, aspectRatio, altText and purpose. Choose the count for creative reasons: the first frame hooks independently and later frames add information. One or three is not a default requirement. The existing publishing contract permits at most ten attachments; never fill that limit merely to consume capacity.

Use `page-image-scope --task <concept> --input <plan.json> --owner-authorized` to record an exact bounded `codex-content-images.v1` plan. The JSON contains taskId, expiresAt, continuity and ordered images (prompt, altText, aspectRatio and purpose). It must match the validated concept and Page. Existing imagery, draft intents or held factual concepts cannot be overwritten. The six-pending-content-item bound remains in force. Scope identity and result hash cannot be rearmed or replaced.

The same existing runner queues one `opening_image` task at a time. Only executor ID `codex_included_images`, configured as a reviewed JSON wrapper at `scripts/agent/codex-content-image.cjs`, may execute tagged tasks. Other executor and provider routes retain their contracts. Every image consumes the existing runner invocation/time/concurrency budget and checks current included Codex availability. The wrapper uses the proven built-in generator, verified final-file handoff and SCC upload code from `91d5dbd`; it is not the paid image API CLI.

Related frames share the immutable continuity brief. When supported by the installed CLI, later requests attach the first verified PNG using `--image`, with its exact hash retained in the request intent. This proves the reference was supplied, not perfect conditioning or visual consistency. Unsupported reference capability holds a related-image request; it does not claim continuity or switch to a paid route.

Artifacts remain under the original Codex thread and are copied unchanged to the sidecar's `content-images/<request ID>/` directory. Successful process completion, original prompt/thread/intent bindings, PNG signature/size/dimensions/hash/full decode and exact SCC read-back precede adoption. Requests, reference hashes, upload identities and completion receipts survive restart. A saved generation intent can only recover its original output/import. Unknown or missing original outcomes hold the scope rather than regenerate. Lost upload responses use exact read-only reconciliation; lost draft responses match the original ordered body before adoption. `page-image-recover --task <image task>` performs import-only original recovery. It cannot call the generator.

Technical adoption prepares the existing ordered image/multi-image draft, unapproved, unqueued and unscheduled. Its generated-image collection explicitly records `creativeAcceptance=false` and consistency/relevance/legibility as owner review. Review the entire collection, caption, alt text and order together in SCC's existing draft workspace. There is no automatic creative PASS or publication authority. Existing owner-supplied imagery reviews remain distinct and are never fabricated for generated images.

Local activation changes only the frozen AgentRunner source and adds its narrowly routed executor. Keep the existing production task/interval, Gemini budgets/holds, Flow and independent Page policies. Do not promote or restart the owner backend merely to use this preparation step. Rollback pauses the runner at idle, preserves protected originals and current databases, restores the previous frozen agent configuration/task using existing controls, then resumes. Never restore an older database over newer receipts.
