# Native Facebook Group handoffs — 3 November 2026

Implemented an additive local ledger on the existing `content_workspace_audit`; no new table, schema migration, connector, scheduler or automatic Facebook action. This extends the existing Group registry, Page-specific membership observations, rules, immutable prepared packages and receipt history. The new source has not been activated in the frozen owner runtime by this workstream.

## Behavior

- `POST /api/groups/:id/native-actions` prepares an exact Page/Group join or prepared-post intent. A stable `requestKey` returns the original intent after a lost response. Another key or cloned prepared-content ID cannot bypass an existing matching intent. Identical post content and media are fingerprinted per Page and canonical Group.
- `GET /api/groups/:id/native-actions` and the existing review/package responses expose durable intents and observations. `POST /api/groups/native-actions/:id/outcome` appends identity-bound, revision-checked evidence. No endpoint opens Facebook or executes the named action.
- A Page join requires an explicitly recorded non-member state, Pages-can-join eligibility, reviewed rules and answered membership questions. A native post requires a matching unpublished prepared post, Group-specific relevance, current review, Page membership and recorded participation/moderation requirements. Unknown requirements and profiles-only restrictions produce a blocked package. The workflow never switches to a personal profile.
- Record `submission_started` immediately before the one authorized native submit action. The worker/operator must inspect existing Facebook state after an interruption. Started, uncertain, pending-membership, pending-moderation and completed attempts cannot be replayed or replaced. Browser disconnection is not evidence that submission failed.
- `awaiting_owner` preserves a complete exportable handoff when the browser cannot act before submission. A known pre-submit failure stays recorded. A blocked, prepared, awaiting-owner or known-pre-submit-failure package can receive an **explicitly reviewed unsent replacement**, requiring the exact old action revision, current Group revision and identity/rules confirmations. This creates a new linked immutable intent and closes the original; it is allowed only if no `submission_started` event exists. Correcting missing rules therefore does not leave a never-submitted handoff permanently stuck.
- Pre-submit checks re-read the actual active real Facebook Page, its external ID, canonical Group, current Group revision and posting readiness. Account archive/external-ID drift fails closed. Historical reconciliation can still append an observation for the original captured identity after later changes.
- Native action exports and ordinary prepared-package exports carry the current derived hold. Superseded packages say `DO NOT SUBMIT` and identify their replacement. Any historically started action says `RECONCILE ONLY`. Original immutable packet text, prepared snapshots and prior audit rows survive.
- Native events distinguish `owner_entered` from `agent_browser_observation`, with explicit observation time, evidence notes and optional Group URL. Resulting publication observations require a native post permalink for the captured Group. All remain `verified:false` / `publicationVerified:false`; a stored link alone does not independently verify a remote post. Existing owner-receipt semantics are unchanged. Native observations do not silently rewrite membership, publishing receipts, Page queues or analytics.

The Groups Planning UI exposes local intent preparation, owner-observation forms, current holds, an explicit unsent-review checkbox/action, and standalone native-action exports. Opening/copying/exporting a package never means it was published. An external Group membership does not establish ownership or administration.
